## 1. 项目概况 (Executive Summary)

### 1.1 项目背景
本项目旨在构建一个高并发、高可用的现代化博客论坛系统。该平台不仅支持传统的图文文章发布，还融合了短视频、动态等多元化内容形式，致力于打造一个集内容创作、知识分享、社交互动于一体的综合性社区。

### 1.2 项目目标
- **构建全端覆盖的社区平台**：实现 PC 端与移动端的无缝适配，提供一致的用户体验。
- **打造高性能微服务架构**：基于 Spring Cloud 构建后端，确保系统具备水平扩展能力，能够应对高并发流量。
- **确保内容与数据安全**：建立完善的内容审核机制与数据备份容灾体系，保障平台合规与数据资产安全。

## 2. 功能需求规格说明 (Functional Requirements)

### 2.1 用户角色体系
系统主要划分为两类角色：**普通用户** 和 **系统管理员**。

| 模块 | 功能点 | 详细描述 |
| :--- | :--- | :--- |
| **内容发布** | 多媒体发布 | 支持富文本文章、短视频上传、短动态（类似朋友圈）发布。 |
| **互动中心** | 点赞/取消点赞 | 对文章、视频、动态、评论进行点赞操作。 |
| | 评论回复 | 支持多级评论回复，支持 @用户功能。 |
| | 关注体系 | 关注感兴趣的创作者，获取其最新动态推送。 |
| | 消息通知 | 接收系统通知、点赞/评论/关注等互动消息（站内信）。 |
| | 收藏夹 | 用户可创建收藏夹，对感兴趣的内容进行归档。 |
| **全站搜索** | 关键词检索 | 支持对文章、视频、用户进行模糊搜索，支持按热度/时间排序。 |
| **社区治理** | 违规举报 | 可对违规文章、恶意评论进行举报，需填写举报理由。 |
| **个人中心** | 资料管理 | 修改头像、昵称、简介、密码等。 |

| 模块 | 功能点 | 详细描述 |
| :--- | :--- | :--- |
| **用户管理** | 用户列表 | 检索所有注册用户，查看用户详情。 |
| | 封禁/解封 | 对违规用户实施账号封禁（可设置期限），或解除封禁。 |

| | 内容删除 | 强制下架或物理删除违规的文章、视频、评论。 |
| **基础配置** | 分类/标签 | 管理文章和视频的分类结构、热门标签配置。 |
| | 运营位管理 | 管理首页轮播图、公告栏内容。 |
| **数据中心** | 数据库备份 | 支持定时自动备份策略配置；支持管理员手动触发全量备份。 |
| | 数据恢复 | 在紧急情况下，可从备份文件回滚数据。 |
| | 数据迁移 | 提供数据导出/导入工具，支持跨环境迁移。 |
| **系统监控** | 仪表盘 | 实时展示 CPU/内存使用率、QPS、活跃用户数等关键指标。 |

## 3. 技术架构方案 (Technical Architecture)

### 3.1 总体架构设计
采用 **前后端分离** + **微服务** 架构。前端负责页面交互与渲染，后端负责业务逻辑与数据处理，通过 RESTful API 进行通信。

### 3.2 技术栈选型

#### 前端 (Frontend)
- **核心框架**: Vue3 + Vite + TypeScript + Vue Router + Pinia
- **UI 组件库**: Element Plus (后台) / uniapp
- **工具库**: 
  - **编辑器**: Vditor (Markdown) / WangEditor (富文本)
  - **视频播放**: Video.js 或 DPlayer
  - **网络请求**: Axios (封装拦截器)
- **设计原则**: 响应式布局 (Responsive Web Design)，一套代码适配 PC 与 Mobile。

#### 后端 (Backend)
- **微服务框架**: Spring Cloud Alibaba (Spring Boot 3.2)
  - **注册中心**: Nacos
  - **配置中心**: Spring Cloud Config 或 Nacos Config
  - **网关**: Spring Cloud Gateway (路由转发、统一鉴权)
  - **远程调用**: OpenFeign
- **安全框架**: Spring Security + OAuth2 + JWT (无状态认证)

#### 数据库与存储 (Data & Storage)
- **关系型数据库**: MySQL 8.0 (主业务数据：用户、文章、评论)
  - *设计要求*: 遵循第三范式，核心表建立适当索引优化查询。
- **缓存中间件**: Redis (热点数据缓存、Session共享、计数器)
- **搜索引擎**: Elasticsearch 7.x+ (支持海量数据的全文检索、高亮显示)
- **消息队列**: RabbitMQ (异步解耦、流量削峰)
  - *应用场景*: 
    - **内容审核**: 用户发布内容后，异步发送消息触发自动审核或人工审核任务。
    - **消息通知**: 点赞/评论后，异步写入消息表并推送给用户。
    - **数据同步**: MySQL 数据变更后，异步同步至 Elasticsearch。
- **对象存储**: 阿里云 OSS (存储图片、视频文件)

#### 运维与监控 (DevOps)
- **任务调度**: XXL-JOB (分布式定时任务，处理备份、统计、清理)
- **链路追踪**: SkyWalking 或 Zipkin (全链路性能监控)
- **系统监控**: Prometheus + Grafana

### 3.3 安全架构
- **网络安全**: 全站 HTTPS 加密传输。
- **应用安全**:
  - **防 XSS**: 统一过滤器处理输入内容，转义特殊字符。
  - **防 SQL 注入**: 使用 MyBatis 预编译 SQL，严禁拼接 SQL。
  
  - **接口限流**: 网关层配置令牌桶算法，防止恶意刷接口。

### 3.4 数据库详细设计 (Database Schema)

系统采用垂直分库设计，共包含 5 个逻辑数据库：

#### 1. 用户库 (`blog_user`)
负责用户身份认证与权限管理，是系统的基石。
- **`sys_user`**: 用户核心表。存储账号、密码（加密）、手机号、头像等基础信息。
- **`sys_role`**: 角色表。定义系统角色（如：普通用户、超级管理员、运营人员）。
- **`sys_user_role`**: 用户-角色关联表。实现多对多关系，控制用户权限。

#### 2. 内容库 (`blog_content`)
负责存储所有对外发布的内容数据，读多写少。
- **`blog_article`**: 文章表。存储标题、Markdown内容、封面图、阅读/点赞计数。
- **`blog_category`**: 分类表。文章的分类管理（如：技术、生活、新闻）。
- **`blog_tag`**: 标签表。文章的标签管理（如：Java, Spring Boot）。
- **`blog_article_tag`**: 文章-标签关联表。

#### 3. 互动库 (`blog_interaction`)
负责用户之间的社交行为，写并发极高。
- **`interaction_comment`**: 评论表。支持文章/视频的评论及盖楼回复。
- **`interaction_like`**: 点赞记录表。记录谁给什么内容点了赞，用于去重和取消点赞。
- **`interaction_follow`**: 关注表。维护用户间的粉丝/关注关系。

#### 4. 消息库 (`blog_message`)
负责系统内部的消息流转，数据量大，增长快。
- **`sys_message`**: 站内信表。存储系统通知、收到的点赞/评论提醒。支持已读/未读状态管理。

#### 5. 管理库 (`blog_admin`)
负责后台运营与审计，安全性要求高。
- **`sys_log`**: 操作日志表。记录全站的关键操作（谁、在什么时间、调用了什么接口、耗时多少），用于审计和排错。
- **`sys_report`**: 举报工单表。存储用户对违规内容的举报记录及管理员的处理结果。

## 4. 项目实施计划 (Project Roadmap)

本计划按 **4 个迭代周期 (Sprints)** 进行规划，每个周期约 2 周。

### 第一阶段：基础设施与用户中心 (Week 1-2)
- [ ] 搭建 Spring Cloud 微服务脚手架 (Gateway, Discovery, Auth)。
- [ ] 数据库设计 (ER 图) 与环境初始化。
- [ ] 实现用户注册、登录 (JWT)、个人信息管理接口。
- [ ] 前端登录页与个人中心页面开发。

### 第二阶段：内容核心模块 (Week 3-4)
- [ ] 文章/动态/视频的发布、编辑、删除接口。
- [ ] 文件上传服务对接 (OSS/MinIO)。
- [ ] 首页信息流接口 (分页查询、排序)。
- [ ] 前端内容发布器与详情页开发。

### 第三阶段：互动与管理体系 (Week 5-6)
- [ ] 点赞、评论、收藏功能的后端逻辑与 Redis 计数器实现。
- [ ] 举报流程开发。
- [ ] 管理后台：用户管理、内容审核界面与接口。
- [ ] 数据库自动备份脚本编写与测试。

### 第四阶段：系统加固与交付 (Week 7-8)
- [ ] 全链路压力测试与性能优化 (SQL 优化、缓存预热)。
- [ ] 安全漏洞扫描与修复 (XSS/SQL 注入测试)。
- [ ] 系统监控面板集成 (Prometheus + Grafana)。
- [ ] 编写部署文档与用户操作手册。

## 5. 风险管理 (Risk Management)

| 风险项 | 可能性 | 影响程度 | 应对策略 |
| :--- | :--- | :--- | :--- |
| **数据丢失风险** | 低 | 极高 | 严格执行每日自动备份，异地留存备份文件；上线前进行恢复演练。 |
| **高并发宕机** | 中 | 高 | 引入 Redis 缓存热点数据；网关层实施限流熔断策略；服务多实例部署。 |
| **内容违规风险** | 高 | 中 | 引入第三方文本/图片自动检测 API (如阿里云内容安全) 辅助人工审核。 |
